# claw-agent 需求与架构文档

> 版本：1.2 ｜ 更新日期：2026-08 ｜ 状态：与代码实现同步
>
> 本文档描述 claw-agent Agent 平台（面向中小企业和个人开发者）的需求范围、前后端分离架构设计，
> 并对三个重点模块给出深入设计说明：**权限系统**、**技能自学习**、**Flyway 表结构演进**。
> 工程结构：仓库根目录下 `backend/`（Spring Boot 后端，本文所有代码路径均相对此目录）与 `frontend/`（Next.js 前端）并列。

## 1. 项目概述

claw-agent 是一个部署在用户自有服务器上的 **Agent 平台**，面向中小企业和个人开发者：

- 基于 **AgentScope Java 2.0 满血版**（`agentscope-harness`），渐进式弹性架构：
  单机模式零依赖启动，多实例模式 Redis 共享状态支持水平扩展；
  按 `(userId, sessionId)` 隔离会话状态；
- **多租户**：租户 → 部门 → 用户三级组织，配置支持 GLOBAL / TENANT / USER 三级作用域就近覆盖；
- 满血接入 AgentScope 能力：工作区人格、分层记忆、上下文压缩、技能自学习、子 Agent、
  Plan Mode、权限系统（HITL 人工确认）、Middleware、流式事件；
- 用户体系：Spring Security + JWT 无状态认证，RBAC（平台管理员 / 租户管理员 / 普通用户）；
- 聊天支持文字 / 图片 / 文件上传（多模态消息）。

## 2. 需求目标与角色

| 角色 | 角色键 | 核心诉求 |
|---|---|---|
| 平台管理员 | `admin`（tenant_id=0） | 跨租户管理租户/用户/菜单；维护平台级模型与 Agent 全局配置、平台预设模板 |
| 租户管理员 | `tenant_admin` | 管理本租户用户/部门；维护租户级模型配置与运行参数；创建租户预设 |
| 普通用户 | `common` | 与 Agent 流式对话、上传附件、选择人格预设、审批敏感操作（HITL）、创建个人预设 |

## 3. 总体架构（前后端分离模式）

### 3.1 分层架构

```
┌──────────────────────────────────────────────────────────────┐
│ 前端（frontend/ 独立 Next.js 16 + React 19 + TS 工程）          │
│  lib/api.ts 统一封装（JWT 注入、错误码、401 跳登录、SSE 流解析） │
│  Zustand 管理认证状态；开发期 rewrites 代理 /api → 后端 :8080   │
└───────────────────────────┬──────────────────────────────────┘
                            │ HTTP JSON（Result<T>）+ SSE（POST + ReadableStream）
┌───────────────────────────▼──────────────────────────────────┐
│ controller —— 只做参数校验与协议转换（WebFlux 响应式）           │
│ service    —— 业务逻辑（AgentService / ConfigService ...）     │
│ mapper     —— MyBatis Plus；自定义 SQL 一律 XML（禁注解 SQL）   │
│ model      —— 实体 + DTO（实体不直接暴露给前端）                │
│ common     —— Result / ResultCode / BizException / 全局异常    │
│ security   —— JwtAuthFilter（WebFilter）/ JwtUtil / LoginUser  │
│ tool       —— AgentScope 自定义工具（@Tool：NoteTools 等）      │
└──────┬─────────────────────────────────────────┬─────────────┘
       │                                         │
┌──────▼──────────────┐                 ┌────────▼─────────────┐
│ MySQL（Flyway 管理）  │                 │ Redis（Agent 会话状态）│
│ 用户/租户/配置/预设…   │                 │ RedisAgentStateStore  │
└─────────────────────┘                 └──────────────────────┘
```

依赖方向严格为 `controller → service → mapper`，禁止反向。

### 3.2 前后端分离边界

| 维度 | 约定 |
|---|---|
| 通信协议 | 前端仅通过 `/api/**` REST（JSON）与 SSE 与后端交互，不依赖服务端模板渲染 |
| 认证方式 | 无状态 JWT：前端登录拿到 token 存 localStorage，每次请求带 `Authorization: Bearer <token>`；**身份一律从 JWT 解析，禁止前端传 userId 决定操作对象（防越权）** |
| 响应契约 | 非流式接口统一 `Result<T>`：`{code, message, data}`，`code=200` 成功；异常由 `GlobalExceptionHandler` 统一转换；时间类型统一下发 `yyyy-MM-dd HH:mm:ss`（`JacksonConfig` + `spring.webflux.format`，请求与响应同格式对称） |
| SSE 契约 | 前端用 `fetch + ReadableStream` 解析（原生 `EventSource` 无法携带 Authorization 头）；事件块以空行分隔，`event:` 行为类型、`data:` 行为 JSON |
| 前端职责 | 页面渲染、token 管理、SSE 分块解析、字典翻译展示；不承载业务规则 |
| 后端职责 | 鉴权、业务校验、Agent 编排、数据持久化；401 时前端自动清 token 并跳 `/login` |
| 部署形态 | 前后端分离独立部署：前端 `frontend/`（Next.js 独立进程/静态导出），后端纯 API 服务；开发期由 Next.js `rewrites` 将 `/api` 代理到 `http://localhost:8080` 免跨域，生产由后端 `CorsConfig`（`claw.cors.allowed-origin-patterns`）放行前端域名 |

### 3.3 技术栈

| 类别 | 选型 |
|---|---|
| 运行时 | Java 17（兼容 21 运行）+ Spring Boot 3.5（WebFlux 响应式，非 MVC） |
| Agent 框架 | AgentScope Java 2.0：`agentscope-harness` + DashScope/OpenAI 兼容/Ollama 模型扩展 + Redis 扩展 |
| 持久化 | MyBatis Plus 3.5.9 + MySQL 8 + Flyway 10 |
| 状态存储 | Redis（`RedisAgentStateStore`，分布式默认）/ JSON 文件（单机开发降级） |
| 认证 | Spring Security Reactive + JJWT 0.12 |
| 前端 | Next.js 16 + React 19 + TypeScript + Tailwind CSS 4 + Base UI/shadcn + Zustand（`frontend/` 独立工程） |

## 4. 功能需求清单

### 4.1 认证与用户体系
- 登录 / 注册 / 获取当前用户信息 / 登出；密码 BCrypt 存储，JWT 有效期可配（默认 24h）；登录成功失败与登出均异步记 `sys_login_log`（fire-and-forget，不拖慢认证响应）；
- 用户管理（租户管理员）：列表、新增、修改、重置密码、删除（级联清理用户-角色关联与会话元数据，登录日志作审计痕迹刻意保留）；密码字段不下发；
- 日志管理（租户管理员及以上）：业务操作日志（`sys_oper_log`，管理端增删改/授权接口由 `ReactiveSupport` 异步记录，成功失败均记）与登录登出日志双 Tab 展示；两类日志均记录访问者 IP（`ClientIpFilter` 解析 X-Forwarded-For → X-Real-IP → 对端地址）；全链路日志带链路跟踪：`TraceFilter` 逐请求生成/透传 `traceId`（响应头 `X-Trace-Id` 回显），经 Reactor 上下文桥接 MDC（业务线程/异步日志线程/安全过滤器与 SSE 对话准备段/上传与匿名接口），日志模式 `%X{traceId}` 输出，一次请求全链路日志可按 traceId 聚合（流式输出段线程持续切换，不在覆盖范围）。

### 4.2 智能对话（核心）
- `POST /api/chat/stream` SSE 流式对话：无 `sessionId` 自动建会话并落库元数据；
- 多模态：图片附件转 Base64 `DataBlock` 直接投喂模型；非图片文件以说明文本告知 Agent 文件位置；
- 预设人格：请求可带 `presetCode`，模板系统提示词叠加在基础人格之上；
- 会话管理：列表（按活跃倒序）、删除（仅元数据，AgentScope 状态由过期策略清理）；
- HITL：敏感工具触发审批事件，前端展示审批按钮，`POST /api/chat/confirm` 批准/拒绝后恢复执行。

### 4.3 三级配置中心（USER > TENANT > GLOBAL）
- 模型提供商配置：提供商（dashscope/deepseek/openai/ollama，DeepSeek 走 OpenAI 兼容协议默认官方端点）、模型名、base-url、API Key（`enc:` AES 加密落库，库中未配时兜底 `<PROVIDER>_API_KEY` 环境变量）、`is_current` 标记生效项；
- Agent 运行参数（KV）：`state_store_type` / `permission_mode` / `compaction_trigger_messages` / `compaction_keep_messages` / `memory_flush_throttle_minutes`；
- 配置变更发布事件，按作用域精准失效 Agent 缓存（GLOBAL 全量 / TENANT 按租户 / USER 按归属人），**热重建无需重启**；失效在事务提交后执行（`@TransactionalEventListener(AFTER_COMMIT)`），避免并发重建读到旧配置；
- 所有 Agent 的状态存储共享单一 Lettuce `RedisClient`（懒加载，`@PreDestroy` 关闭），避免重建时连接/事件循环泄漏。

### 4.4 预设模板 / 流水线 / 提示词模板
- 预设 Agent（`agent_preset`）：PLATFORM / TENANT / USER 三级，Markdown 人格；内置 6 个（通用/研究/编程/写作/翻译/运维）；
- 流水线（`agent_pipeline`）：多步骤执行剧本 + 异常处理策略；
- 提示词模板（`prompt_template`）：`{{变量}}` 占位符，前端填参后发送。

### 4.5 字典
- 若依风格 `sys_dict_type` / `sys_dict_data`（`tenant_id=0` 为平台公共）；
- 已内置：通用状态、模型提供商、权限模式（五档）等枚举翻译。

### 4.6 文件上传
- `POST /api/upload`（multipart）；扩展名白名单 + 大小上限（默认 20MB）+ 路径防目录穿越；
- 存储于 `D:/claw-agent/data/uploads/{userId}/`，按用户目录隔离。

### 5.3 接口权限矩阵（谁需要权限才能调）

鉴权分三级：**匿名放行 → 登录即可 → 角色限定**，均在后端强制，前端仅做展示层隐藏。

| 分级 | 接口 | 要求 | 实现位置 |
|---|---|---|---|
| 匿名放行 | `POST /api/auth/login`、`POST /api/auth/register` | 无需 token（前后端分离，后端不再承载静态资源） | `SecurityConfig` `permitAll()` + `AuthController` 方法级 `@PreAuthorize("permitAll()")` |
| 登录即可 | 对话 `/api/chat/**`、上传 `/api/upload`、字典 `/api/dict/**`、配置 USER 作用域、预设本人/租户级 | 有效 JWT（401 拒绝） | `SecurityConfig` `anyExchange().authenticated()` + `JwtAuthFilter` + 控制器类级 `@PreAuthorize("isAuthenticated()")` |
| 租户管理员及以上 | `/api/admin/user/**`（用户列表/新增/改/重置密码/删除/分配角色）、`/api/admin/role/**`（角色 CRUD + 菜单授权）、`/api/admin/dept/**`（部门 CRUD）、`/api/admin/menu/list`、`/api/admin/menu/{id}/roles`（菜单关联角色，按本租户收窄）、`/api/admin/log/**`（操作/登录日志查询）、`/api/config/**?scope=TENANT` | 角色 `tenant_admin` 或 `admin`，数据限本租户 | `SecurityConfig` `hasAnyRole("ADMIN","TENANT_ADMIN")` + 控制器类级 `@PreAuthorize("hasAnyRole('ADMIN','TENANT_ADMIN')")` + 控制器内租户过滤 |
| 平台管理员 | `/api/admin/tenant/**`（租户 CRUD）；`/api/admin/menu` 增删改（菜单为平台级数据）；`GET/POST /api/config/**?scope=GLOBAL`；预设 `PLATFORM` 级改删 | 角色 `admin` | `TenantController` 类级 / `MenuController` 增删改方法级 `@PreAuthorize("hasRole('ADMIN')")`；`ConfigController.checkScopePermission()` / `PresetService` 记录归属校验（scope 为运行时入参，无法静态表达式判定） |
| 按钮级 | 用户/角色/部门的增删改与授权操作（如 `POST /api/admin/user` 需 `system:user:add`） | 持有对应权限点（V12 F 型按钮，角色授权菜单聚合），平台管理员经 `hasRole('ADMIN')` 短路 | 控制器方法级 `@PreAuthorize("hasRole('ADMIN') or hasAuthority('...')")`；权限点随 JWT `permissions` 声明下发，`JwtAuthFilter` 授予为 authority；前端 `hasPerm()` 控制按钮显隐（仅展示层） |

> 除角色鉴权外，所有业务接口内再做**租户隔离**：数据一律按当前用户 `tenantId` 过滤（如 `UserServiceImpl.selectInTenant` 跨租户访问直接 404），身份从 JWT 解析，不信任前端传参。
> 分层遵循规约：Controller 按模块分包（`controller/auth|chat|agent|system`）且只做参数校验与协议转换，需登录的阻塞式接口一律走 `common.ReactiveSupport.call/run`（增删改重载自动记 `sys_oper_log` 操作日志）；Service 采用 MyBatis Plus 接口+实现范式（接口 `extends IService<T>`，实现 `extends ServiceImpl<Mapper, Entity>`，位于 `service/impl`）：`UserService`、`TenantService`、`DeptService`、`RoleService`、`MenuService`、`DictService`、`PresetService`、`OperLogService`、`LoginLogService`，认证业务在 `AuthService`；实体继承 `BaseEntity`，六审计字段（创建/修改时间、创建/修改人用户名及其 ID）由 `AuditMetaObjectHandler` 自动填充（ID 来自 JWT 的 `userId` 声明，V10 补列）；角色键等魔法值统一收拢在 `common/RoleConstants`。
> 未认证统一返回 JSON `{code:401}`（不跳页）；`@PreAuthorize` 拒绝由 `GlobalExceptionHandler` 的 `AccessDeniedException` 处理器转 JSON `{FORBIDDEN}` + HTTP 403（方法级拦截不走 Security 的 accessDeniedHandler，否则会被兜底处理器吞成 500）。

## 6. 权限系统深入设计（双层模型）

平台权限分两层，**互不替代**：

### 6.1 平台层：多租户 RBAC（谁能访问系统功能）

```
租户 sys_tenant ─┬─ 部门 sys_dept（树形，ancestors 存父链）
                 └─ 用户 sys_user ── sys_user_role ── 角色 sys_role
                                                        │
                                     sys_role_menu ── 菜单/权限点 sys_menu（M/C/F）
                                                        │
                              数据权限 sys_role.data_scope + sys_role_dept
```

- 菜单权限点格式 `模块:对象:动作`（如 `system:user:add`），F 型按钮粒度；
- 数据权限沿用若依五档：1 全部 / 2 自定义（`sys_role_dept`）/ 3 本部门 / 4 本部门及以下 / 5 仅本人；
- 内置三角色：平台管理员（全菜单）> 租户管理员（除租户管理）> 普通用户（仅智能对话）；
- 运行时落地：`JwtAuthFilter` 解析 JWT 中角色键 → 映射 `ROLE_<KEY>` 权限 → 写入
  `ReactiveSecurityContextHolder`，Controller 用 `hasRole` / `@PreAuthorize` 校验。
- RBAC 相关代码索引：
  | 职责 | 文件 |
  |---|---|
  | 路径级鉴权规则（匿名/登录/角色） | `config/SecurityConfig.java` |
  | JWT 解析与角色→权限映射（不带 @Component，仅由 `SecurityConfig` 声明 Bean 挂安全链，防全局链双注册重复解析） | `security/JwtAuthFilter.java` |
  | 登录用户上下文（用户ID/租户/角色键） | `security/LoginUser.java`、`security/SecurityUtil.java` |
  | 作用域级细粒度鉴权（GLOBAL/USER） | `controller/agent/ConfigController.java` |
  | 预设平台级保护 + 租户数据隔离 | `service/impl/PresetServiceImpl.java`、`service/impl/UserServiceImpl.java` |
  | 组织管理业务规则（唯一性/删除保护/全量替换授权/防环） | `service/UserService`、`TenantService`、`DeptService`、`RoleService`、`MenuService`（接口）+ `service/impl/*Impl`（实现，`ServiceImpl<Mapper, Entity>` 范式） |
  | 响应式样板消除 + 操作日志统一记录 | `common/ReactiveSupport.java`、`common/UserContextHolder.java`、`common/SpringContextHolder.java` |

### 6.2 Agent 层：工具权限 + HITL（Agent 能动什么）

由 AgentScope 权限系统实现，`AgentRegistry.buildPermissionContext()` 装配：

- **权限模式**（数据库 `permission_mode`，三级作用域可覆盖）：
  `DEFAULT`（逐项确认）/ `ACCEPT_EDITS`（自动放行编辑）/ `EXPLORE`（只读）/
  `BYPASS`（全放行）/ `DONT_ASK`（无人值守，ASK 转 DENY）；
- **放行规则**：只读类工具（`read_file`、`grep`、`glob`、`ls`、`memory_search`、`memory_get`、`todo_write`）自动 ALLOW，不打扰用户；
- **强制确认规则**：危险操作（`dangerous_delete`、`drop_table`、`force_push`）无论模式一律 ASK；
  危险路径（`.ssh/`、`.env`、`.git/`）写操作由框架内置检查强制拦截；
- **HITL 交互闭环**：
  ```
  Agent 触发敏感工具 → RequireUserConfirmEvent
    → HitlPendingStore 写入 Redis Hash（claw-agent:hitl:pending）
    → SSE confirm_request 事件 → 前端审批按钮
    → POST /api/chat/confirm → ConfirmResult 注入 Msg metadata
    → streamEvents 恢复执行
  ```
- **多实例支持**：`HitlPendingStore` 已迁移到 Redis Hash，负载均衡将审批请求打到任意节点均可恢复执行；Redis 不可用时自动降级为内存 ConcurrentHashMap（仅支持单实例）。

### 6.3 前端权限控制（展示层，不替代后端鉴权）

| 控制点 | 行为 | 实现位置 |
|---|---|---|
| 路由守卫 | 未登录访问任意页面 → 跳 `/login`；401 响应自动清 token；`/system/user`、`/system/role`、`/system/dept`、`/system/menu`、`/system/log` 另要求租户管理员及以上（`requireTenantAdmin`）；`/system/tenant` 另要求平台管理员，普通用户直输地址拦回首页 | `lib/use-auth-guard.ts`、`lib/api.ts`、`app/system/tenant/page.tsx` |
| 菜单显隐 | 「用户/角色/部门/菜单/日志管理」仅租户管理员及以上可见；「租户管理」仅平台管理员可见；「Agent 配置」全员可见（普通用户仅 USER 作用域）；页内增删改按钮另按权限点（`hasPerm`）显隐 | `components/app-shell.tsx` `adminOnly`/`platformOnly` 过滤、`store/auth.ts` `hasPerm()` |
| 页内按钮分级 | 菜单管理页：新增/编辑/删除按钮仅持 `system:menu:*` 权限点者渲染（平台管理员持通配 `*:*:*`），关联角色按钮租户管理员可用 | `app/system/menu/page.tsx` |
| 作用域可选范围 | 配置页作用域胶囊：普通用户仅 USER；租户管理员 +TENANT；平台管理员 +GLOBAL | `app/system/config/page.tsx` |
| 平台模板保护 | 预设页 PLATFORM 磁贴仅平台管理员可编辑/删除，其余用户点击提示 | `app/presets/page.tsx` `canModify()` |
| 角色判定源 | 登录响应 `roles[]` 存 localStorage；`isAdmin`/`isTenantAdmin` 由 Zustand 派生 | `store/auth.ts` |

> 原则：前端所有权限控制仅为体验优化（藏入口），**绕过前端直调接口时后端必拦**（见 §5.3 矩阵）。

### 6.4 安全硬性要求

1. 密码仅 BCrypt，禁明文与可逆加密；
2. JWT secret 生产环境必须替换（环境变量/配置中心），不入库不入前端；
3. API Key 落库一律 `enc:` 前缀 AES 加密，读取时由 `ConfigService` 解密，永不明文下发；
4. 文件上传：扩展名白名单 + 大小上限 + `..` 目录穿越拦截；
5. 所有登录接口从 JWT 取身份，防越权。

## 7. 技能自学习深入设计

目标：让 Agent 把高频操作经验**自动沉淀为可复用技能文件**，形成学习闭环。

### 7.1 技能文件形态

存放于用户工作区 `D:/claw-agent/.agentscope/workspace/{tenantId}/{userId}/skills/<技能名>/SKILL.md`，
YAML frontmatter + Markdown 正文：

```markdown
---
name: web-digest
description: 把一组搜索关键词或网页要点整理成结构化摘要卡片
---
## 适用场景 / ## 步骤 / ## 注意事项
```

工作区按「租户/用户」物理分目录，技能、人格（AGENTS.md）、知识（knowledge/）、
子 Agent（subagents/）、笔记天然互相隔离。

### 7.2 学习闭环（AgentRegistry 装配）

| 环节 | 实现 | 说明 |
|---|---|---|
| 起草 | `enableSkillManageTool(SkillManageConfig.defaults())` | Agent 可调用 `propose_skill` / `skill_manage` 工具，把重复操作流程起草为技能草稿（草稿 → 审核两步流程） |
| 应用 | 工作区技能自动加载 | 命中适用场景时按技能步骤执行 |
| 整理 | `enableSkillCurator`（每 7 天） | 后台 curator 自动维护：30 天未用标记 `stale`，90 天归档，防止技能目录膨胀 |

### 7.3 与配套资产的关系

- **预设模板**（`agent_preset`）= 人格（系统提示词），**技能** = 操作手册（过程性知识），二者正交；
- **流水线**（`agent_pipeline`）是人工固化的多步骤剧本，技能是 Agent 自主沉淀的，
  均可作为“把经验产品化”的手段。

## 8. 数据库设计与 Flyway 演进

### 8.1 迁移规约（硬性）

- 脚本位置 `backend/src/main/resources/db/migration/V<n>__<描述>.sql`，**只增不改**（已执行脚本修改触发校验失败），版本递增；
- 脚本内部保持幂等（`CREATE TABLE IF NOT EXISTS` / `INSERT ... WHERE NOT EXISTS` /
  条件化 `ALTER`）；
- 表规约：小写下划线命名，必备 `id` / `create_time` / `update_time`，
  索引 `uk_`（唯一）/ `idx_`（普通）前缀，删除优先逻辑删除。

### 8.2 演进时间线

| 版本 | 主题 | 内容摘要 |
|---|---|---|
| V1 | 基础表 | `sys_user`（含旧 role 列）、`chat_session` |

### 8.3 表全景与关键关系

```
组织域：  sys_tenant ─< sys_dept ─< sys_user ─< sys_user_role >─ sys_role
权限域：  sys_role ─< sys_role_menu >─ sys_menu        sys_role ─< sys_role_dept >─ sys_dept
配置域：  model_provider_config / agent_config（scope+tenant_id+owner_name 三级）
资产域：  agent_preset / agent_pipeline / prompt_template（同为三级作用域结构）
字典域：  sys_dict_type ─< sys_dict_data（tenant_id=0 平台公共）
会话域：  chat_session（username+session_id 唯一，挂租户审计）
```

三级作用域表统一模式：`scope ∈ {GLOBAL/TENANT/USER(或 PLATFORM)}` +
`tenant_id`（全局为 0）+ `owner_name`（用户级归属）+ 业务唯一键，
解析由 `ConfigService.resolveValue()` 按 USER → TENANT → GLOBAL 就近覆盖。

### 8.4 新增表结构的操作流程

1. 新建 `V<下一版本号>__<描述>.sql`（禁改历史脚本）；
2. 建表含三必备字段 + 注释 + 索引前缀规约；
3. 种子数据用 `WHERE NOT EXISTS` 幂等写法；
4. 启动即由 Flyway 自动执行（`validate-on-migrate: true` 防篡改）。

## 9. 非功能需求

| 维度 | 要求 |
|---|---|
| 并发模型 | 同一 `(userId, sessionId)` 由 AgentScope 自动串行化；WebFlux 全链路响应式，禁止阻塞调用 |
| 会话恢复 | 状态默认存 Redis（key 前缀 `claw-agent:session:`），任意节点可恢复会话，支持多实例 |
| 上下文治理 | 超阈值自动压缩（默认 30 条触发、保留 10 条）；超大工具结果落盘只留占位符 |
| 成本控制 | 长期记忆 flush 节流（默认 10 分钟），限制辅助 LLM 调用频率 |
| 可观测 | `AgentTraceMiddleware` 执行链路追踪；日志 Slf4j 占位符风格，异常带堆栈 |
| 文件上传 | 内存缓冲上限 50MB（`spring.codec.max-in-memory-size`），单文件默认 20MB |

## 10. 部署依赖

- MySQL 8：预建库 `claw_agent`（utf8mb4），账号可配（默认 root，环境变量 `MYSQL_HOST`/`MYSQL_USER`/`MYSQL_PASSWORD` 覆盖）；
- Redis 6+：Agent 状态存储（单机开发可将数据库配置项 `state_store_type` 改为 `json`）；
- JDK 17（兼容 21 运行）；后端服务端口 8080；**启动工作目录必须是 `backend/`**（AgentScope 工作区与上传目录为相对路径）；生产通过 `CLAW_JWT_SECRET` / `CORS_ORIGINS` 环境变量覆盖密钥与跨域白名单；
- Node.js 20+：前端 `frontend/` 独立部署（`npm run dev` 开发 / `npm run build && npm start` 生产），`BACKEND_URL` 环境变量指定后端地址（默认 `http://localhost:8080`）；
- 至少一个可用模型提供商（默认 GLOBAL 配置为 dashscope `qwen-plus`，需补 API Key；也可切 DeepSeek（`DEEPSEEK_API_KEY`）或 `ollama` 免 Key 本地模型）。
